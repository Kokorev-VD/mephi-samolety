# Комплект проектной документации — криптотренажёр mephi-12

Полное наименование системы: **«Платформа для изучения и практики курса по криптографии в МИФИ»**
(краткое — **криптотренажёр mephi-12**). Настоящий репозиторий содержит комплект проектной
документации backend-части платформы (Kotlin 1.9.25 + Spring Boot 3.4.0, PostgreSQL 17, JWT,
Docker), подготовленный по образцу авиационных стандартов **DO-178C / КТ-178C**: цепочка
«ТЗ → системные требования → программные требования → трассировка» с формальными инспекциями
по Фагану и планами верификации. Комплект выполняется командой из 6 человек в рамках курсовой
работы НИЯУ МИФИ; сдача — 01.12.2026. Объект документирования: 7 REST-контроллеров (14 действующих
эндпоинтов, базовый путь `/api`; см. notes/api/endpoints.md), 8 JPA-сущностей, монолит со слоистой архитектурой, пакет
`ru.command.mephi12`. Тестовый код не пишется и прогоны не выполняются (решение от 20.10).

**Статус: Спринт 1 (20.10–24.10.2026) выполнен.** Дата фиксации — 24.10.2026.
Выпущены DOC-00 v1.0, DOC-01 v1.0, DOC-04 v1.0, DOC-02 v0.5, DOC-03 v0.5, скелет DOC-05 v0.1,
рабочие материалы в `notes/`.

## Правила работы с комплектом

- **Версии.** Каждый документ — элемент конфигурации по ПУКПО (DOC-03): версия на титуле,
  заполненный лист регистрации изменений; формат `tex+pdf` (LaTeX + собранный PDF в коммите).
- **Теги и ветки.** Выпуск версии фиксируется тегом `docs/<DOC-ID>-v<версия>`
  (например, `docs/DOC-00-v1.0`); работа ведётся в ветке `docs/<DOC-ID>`, в `main` попадают
  готовые версии.
- **Формальные инспекции.** Каждый документ приоритета К и В проходит формальную инспекцию
  по процедуре DOC-04 (роли: автор, ведущий, секретарь, рецензенты; правило перекрёстности —
  рецензент всегда проверяет чужой домен) с решением «ПРИНЯТО» или «ПРИНЯТО С ЗАМЕЧАНИЯМИ».
- **Дефекты.** Замечания инспекций и правки учитываются в реестре дефектов `defects.md`
  (идентификаторы DEF-XXX).
- **Инварианты комплекта** (проверяются на приёмке 01.12.2026):
  1. Каждый документ имеет титул с ролями «Разработал / Согласовано / Утверждено» и заполненный лист регистрации изменений.
  2. Каждый документ приоритета К и В прошёл формальную инспекцию с решением «ПРИНЯТО» или «ПРИНЯТО С ЗАМЕЧАНИЯМИ», и все замечания закрыты.
  3. Каждое системное требование `[SR.*]` трассируется минимум на одно `[SWR.*]` и минимум на один верификационный кейс TC из плана верификации DOC-10.
  4. Все документы сведены в README комплекта (DOC-00) и описаны в DOC-01.
  5. Финальные PDF собраны из зафиксированных тегами версий исходников.

## Сборка

- Дистрибутив LaTeX — **MiKTeX 25.12**; сборка — `pdflatex` (два прохода для оглавления).
- Каждый документ — файл `.tex`, оформленный по единому шаблону
  `01_Шаблоны_документов/full_doc_template.tex` (12pt, T2A, babel russian, newtx, титул с ролями,
  лист регистрации изменений), плюс собранный PDF, зафиксированный в коммите.
- Трассировка (DOC-09) ведётся в CSV, в комплект включается её PDF-версия.
