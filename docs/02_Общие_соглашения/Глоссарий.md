# Глоссарий

Версия 0.4 от 20.11.2026. Ответственный — Анохин Г.А.

Криптотренажёр — учебная платформа, на которой преподаватель готовит работы по курсу, а студент получает условия, сдаёт ответы и читает результаты. Ниже разобраны обозначения, которые встречаются в техническом задании, требованиях и описаниях проверок.

## Задание и вариант

**Задание** определяет, что нужно сделать студенту. **Условие** — данные и вопрос, которые он видит. **Вариант** задаёт одно конкретное условие. Один и тот же вопрос о переводе единиц можно задать для разных исходных чисел. Для **авторского задания** преподаватель вводит одну или несколько пар «условие — правильный текстовый ответ». Этот сохранённый правильный ответ называется **эталоном**. При выдаче система случайно выбирает одну пару. Студент получает условие. Его ответ проверяется по эталону именно этой пары. Правила сравнения заданы в [`TS.REQ.FUNC.TASK.ASSIGN`][TS.REQ.FUNC.TASK.ASSIGN].

**Тип задания** определяет, как выдать условие, какие поля студент должен заполнить и как проверить его решение. **Модуль заданий** — часть программы, которая выполняет эти действия для определённого типа. Для ранцевой задачи (`BACKPACK`) и задачи по схеме Эль-Гамаля (`EL_GAMAL`) модуль готовит учебные числа и проверяет вычисления. Для текстового задания (`CUSTOM_TEXT`) он использует варианты преподавателя. **Схема ответа** перечисляет поля решения и допустимые типы значений. По ней приложение студента определяет, что предложить для ввода. Устройство модулей и учебное содержание описаны в [`TS.REQ.FUNC.TASK.MODULE`][TS.REQ.FUNC.TASK.MODULE], [`TS.REQ.FUNC.PROB.BACKPACK.SI`][TS.REQ.FUNC.PROB.BACKPACK.SI] и [`TS.REQ.FUNC.PROB.ELGAMAL`][TS.REQ.FUNC.PROB.ELGAMAL].

## Работа группы и расписание

**Пользователь** работает под собственной учётной записью платформы. **Привязка учётной записи МИФИ** связывает существующий профиль студента с подтверждённой учётной записью на home.mephi.ru. Студент также может использовать её при регистрации. **Учебная группа студента** определяется по номеру группы, полученному платформой из подтверждённых сведений МИФИ. По этой группе студенту доступны расписание и шаблоны для практики. [Личный кабинет студента НИЯУ МИФИ](https://mephi.ru/students/cab), [правило определения группы](../02_Техническое_задание/DOC-02_Техническое_задание.md#ts-req-func-group-join).

**Управляемые группы преподавателя** — группы, которые администратор (роль `ADMIN`) назначил преподавателю (роль `TEACHER`). В эти группы преподаватель может назначать свои работы и просматривать результаты по ним. Администратор имеет право просматривать сессии всех студентов. [Разграничение прав](../02_Техническое_задание/DOC-02_Техническое_задание.md#ts-req-sec-roles).

**Контрольное мероприятие** (контрольная работа) — работа для одной группы. Преподаватель задаёт название, составляет упорядоченный список заданий и выбирает, разрешить ли повторное прохождение. Место задания в списке называется **позицией**. Две позиции могут иметь один тип и давать разные задачи.

**Черновик** — состояние, в котором преподаватель готовит работу. Черновик скрыт от студентов и может быть пустым. Для **публикации** нужна хотя бы одна позиция. При публикации преподаватель выбирает группу и указывает начало и конец работы. Система закрепляет её состав, настройку повторного прохождения и назначение. Состояние работы теперь — **«Опубликовано»**. **Карточка расписания** — запись с названием работы, временем начала и конца и признаком доступности старта. Она видна назначенной группе с момента публикации.

**Окно проведения** — время от открытия до закрытия по часам сервера. В момент открытия приступить уже можно, в момент закрытия приём новых стартов и ответов заканчивается автоматически. Таким образом, завтрашнюю контрольную группа увидит сегодня, если преподаватель уже опубликовал её. Условия для старта приведены в [`TS.REQ.FUNC.EVENT.PUBLISH`][TS.REQ.FUNC.EVENT.PUBLISH], [`TS.REQ.FUNC.EVENT.VIEW`][TS.REQ.FUNC.EVENT.VIEW] и [`TS.REQ.FUNC.EVENT.START`][TS.REQ.FUNC.EVENT.START].

## Личная сессия и самостоятельная практика

**Сессия задач** — запись одного прохождения работы одним студентом. При старте система создаёт **выданный набор** — конкретные задачи по позициям работы с собственными идентификаторами и условиями. **Идентификатор** позволяет однозначно найти запись. Один студент может читать одну и ту же задачу несколько раз. При этом **закреплённый вариант** остаётся тем, который система выдала ему для этой позиции в данной сессии.

**Повторное прохождение** создаёт для того же студента новую сессию по тому же мероприятию. Оно доступно после завершения первой сессии, если преподаватель разрешил повтор и окно проведения ещё открыто. При повторном открытии существующей сессии сохраняются её варианты и результаты. История каждого завершённого прохождения остаётся доступной студенту.

У набора два возможных источника. На контрольной состав берётся из опубликованного мероприятия, а результат относится к этому мероприятию. Для **самостоятельной практики** студент выбирает доступный своей группе **шаблон набора задач** — именованный список типов в заданном порядке. Сервер создаёт личную тренировочную сессию по шаблону. Позднейшее изменение шаблона не меняет выданные условия. Отдельно студент может запросить **редакционный пример** — учебное условие или готовый разбор вне сессии. Выдача набора и примера описана в [`TS.REQ.FUNC.SESSION.CREATE`][TS.REQ.FUNC.SESSION.CREATE] и [`TS.REQ.FUNC.EDITORIAL`][TS.REQ.FUNC.EDITORIAL].

## Ответ, попытка и состояние

**Предметная проверка** устанавливает, правилен ли ответ студента на выданное ему условие. **Вердикт** — сохранённый вывод «верно» или «неверно». **Попытка** — возможность сдать решение конкретной задачи. Она расходуется при записи вердикта. При **ошибке формата** отсутствует нужное поле, передано значение неподходящего типа или сообщение невозможно прочитать. При **техническом сбое** обработка прервалась без вердикта. В обоих случаях студент может отправить исправленный или новый ответ, пока соблюдаются срок и остальные условия допуска. **Неверный ответ** имеет допустимую форму и отрицательный вердикт. Детали даны в [`TS.REQ.FUNC.SESSION.SUBMIT`][TS.REQ.FUNC.SESSION.SUBMIT].

| Состояние | Для одной выданной задачи | Для сессии целиком |
|---|---|---|
| `NEW` | Окончательного результата пока нет. Для нового ответа отдельно проверяются срок и наличие уже начатой проверки | Хотя бы одна задача ещё не завершена |
| `SOLVED` | Ответ признан верным | Все задачи решены верно |
| `FAILED` | Ответ неверен и есть вердикт с пояснением, либо истёк срок без вердикта | Все задачи завершены и хотя бы одна из них получила `FAILED` |

**Итоговое состояние** — `SOLVED` или `FAILED`. Время получения ответа — момент, когда сервер принял полный запрос. **Своевременный ответ** поступил строго до общего срока сессии. Для самостоятельной практики срок наступает через 20 минут после старта. На контрольной действует более ранний из двух моментов — конец этих 20 минут или закрытие мероприятия. Для записи вердикта по нему действует отдельный предел времени. Обозначения и пограничные случаи приведены в [`TS.REQ.FUNC.SESSION.TIME`][TS.REQ.FUNC.SESSION.TIME].

## Как читать ссылки на требования

**Контракт** описывает, какие данные принимает участник взаимодействия, что гарантирует в ответ и по каким причинам может отказать. **Системное требование** (SR) описывает результат, который должна обеспечить платформа. **Программное требование** (SWR) определяет обязанность компонента программы для получения этого результата. **Проверочный сценарий** (TC) задаёт исходные условия, действия и ожидаемый результат. **Трассировка** связывает эти записи по идентификаторам. **Формальная инспекция** (ФИ) — разбор определённой редакции документа назначенными участниками с регистрацией замечаний и решения. Порядок чтения обозначений приведён в [методике идентификаторов](Методика_идентификаторов.md#форматы).
