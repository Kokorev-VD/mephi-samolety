## 1. Назначение и границы

Преподаватель готовит для группы студентов работу с оценкой решений. Такая работа называется **контрольным мероприятием**. В неё можно включать как задания, составленные преподавателем, так и задачи, условия которых формирует программа. После публикации группа видит в расписании название и время автоматического открытия и закрытия мероприятия. Студент начинает работу в разрешённое время, получает собственные условия и затем читает результаты. Просмотр работ всех студентов называется **модерацией** и требует отдельного права.

Права определяет роль: студент `USER` выполняет собственные задания, преподаватель `TEACHER` ведёт работы только назначенных ему групп, администратор `ADMIN` закрепляет группы за преподавателями и видит сессии студентов всех групп. Номер группы студента поступает из подтверждённой учётной записи МИФИ на `home.mephi.ru` при регистрации или привязке к собственному профилю. Действия человека передаёт серверу клиент — программа, через которую студент или преподаватель работает с платформой. Требования определяют, какие запросы сервер принимает, какие данные сохраняет и что возвращает клиенту. Например, сведений в расписании должно хватать, чтобы отличить предстоящую работу от той, которую уже можно начать.

| Объект | Что он обозначает |
|---|---|
| Подключаемый вид задания | Вид, для которого разработчик подключил программный модуль. Модуль формирует условие и проверяет ответ. Среди поставляемых видов — [задачи на шифрование взвешенной суммой](Ранцевые_задачи.md) и [задачи на шифрование по схеме Эль-Гамаля](Платформенные_и_предметные_требования.md#sr-elg-001-условие-и-результат-задачи-эль-гамаля) |
| Авторское задание | Текстовое задание преподавателя с одним или несколькими вариантами. Вариант — пара из условия для студента и закрытого эталона, то есть правильного ответа для проверки |
| Позиция в работе | Место задания в упорядоченном списке. Даже если вид задания повторён, у каждой позиции своя задача и свой результат |
| Шаблон набора задач | Именованный состав и порядок типов заданий для учебного набора. Один и тот же тип может встретиться в шаблоне несколько раз. Преподаватель может собрать мероприятие и без готового шаблона |
| Контрольное мероприятие | Подготовленная преподавателем учебная работа. Черновик позволяет собрать состав до публикации |
| Назначение и публикация | Назначение связывает мероприятие с группой и интервалом доступности. При публикации сохраняется разрешение или запрет повторного прохождения. Публикация делает это назначение видимым в расписании студентов |
| Личная сессия студента | Выданный студенту экземпляр работы. В нём закреплены условия и варианты позиций, собственное время создания, состояния и результаты |

Два студента одной группы могут выполнять одно мероприятие. Каждый получает свою сессию. По каждой задаче сохраняется **предметный вердикт** — вывод о том, правильно ли студент решил именно эту задачу. Изменение шаблона не подменяет уже выданные условия.

## 2. Основные сценарии и результаты

**Из чего собрать работу.** Преподаватель готовит черновик мероприятия и задаёт порядок позиций. В одну работу могут войти, например, ранцевая задача, авторское задание с несколькими вариантами и задача Эль-Гамаля. У авторского задания преподаватель сам вводит условие и эталон каждого варианта. Если требуется новый способ генерации или программной проверки, разработчик подключает новый модуль по общему контракту.

**Когда группа увидит мероприятие.** Преподаватель может сохранить пустой черновик. Для публикации требуются хотя бы одно задание, назначенная преподавателю группа, моменты открытия и закрытия и явное решение о повторах (`repeatAllowed`). Сервер автоматически открывает работу в `opensAt` и закрывает в `closesAt`, при этом `opensAt < closesAt`. Запись появляется в расписании подтверждённой группы сразу после публикации, в том числе до открытия. Чтение расписания не выдаёт студенту условий и не начинает личную сессию.

**Что получает студент.** Сервер устанавливает членство в группе по подтверждённому университетскому профилю студента. Ручной выбор группы права на старт не даёт. При разрешённом старте сервер выдаёт ему целый личный набор в порядке позиций мероприятия. Для позиции с авторским заданием он случайно выбирает один из подготовленных вариантов, сохраняет соответствующий эталон на стороне сервера и передаёт студенту только условие. Вновь открыв ту же сессию, студент видит прежние условия. Каждое решение проверяется по первоначально выданной задаче. Фиксация предметного вердикта расходует её единственную попытку. Ошибка формы и технический отказ без вердикта оставляют попытку неиспользованной.

**Сроки и восстановление.** Момент создания личного набора обозначается `t0`, срок получения решений — `D`. Для самостоятельной практики `D = t0 + 20 минут`. Для контроля действует более ранняя из двух границ: `D = min(t0 + 20 минут, closesAt)`. Момент получения полного запроса обозначается `t_in`. Только ответ с `t_in < D` может пройти проверку. Для своевременного ответа владельца вердикт может быть сохранён строго до `L = t_in + 60 секунд`, даже если мероприятие уже закрылось. Планировщик — часть системы, которая проверяет просрочку без участия студента каждые 60 секунд. Задержка фонового цикла или перезапуск не сдвигают ни одну границу.

**Получение итога.** Пока хотя бы одна задача не завершена, сессия остаётся `NEW` («работа продолжается»). После завершения всех задач положительный итог `SOLVED` возможен только при верном решении каждой. Если среди завершённых есть хотя бы одна неверно решённая или просроченная задача, итог сессии — `FAILED` («завершена без успеха»). Если ответ сервера потерян после фиксации вердикта, владелец читает прежний результат по идентификатору своей сессии. У просроченной задачи состояние `FAILED` сопровождается отсутствием предметного результата, у неверного решения — сохранённым отрицательным вердиктом.

**История, модерация и самостоятельная практика.** Для контрольного мероприятия основанием служит опубликованное назначение группе, для самостоятельной практики — включённый шаблон этой группы. В обоих случаях сессия и результаты принадлежат студенту. Личная история показывает его решения. Преподаватель читает результаты участников своего мероприятия только пока его группа закреплена за преподавателем. Администратору доступны сессии всех групп, в том числе самостоятельная практика. При запрете повторного прохождения студент после завершения читает прежнюю работу. При разрешении повтора новый старт до закрытия создаёт отдельную сессию. Повтор при действующей сессии не создаёт дубликат. Редакционный пример — отдельный учебный материал для самоподготовки. Его просмотр не создаёт сессии и не расходует предметную попытку.

Факт принятия редакции фиксируется в протоколе соответствующей инспекции.
