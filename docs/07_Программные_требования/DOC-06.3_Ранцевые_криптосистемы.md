## 1. Назначение и состав

Студент получает исходные данные учебного шифра, вычисляет недостающие величины и показывает, как из шифротекста получается исходное сообщение. В личной сессии платформа сохраняет выданное условие и проверяет решение студента. Для самоподготовки можно запросить отдельный пример с полным решением. В документе такая выдача называется редакционной генерацией. Её результат не входит в оценку сессии.

### Как устроена ранцевая задача

Ранец в этой задаче — упорядоченный список положительных целых чисел, или весов. Позиции списка соответствуют битам сообщения. Бит равен нулю или единице. При шифровании складывают веса на тех позициях, где в сообщении стоит единица. Полученная сумма называется шифртекстом. Например, для весов 10, 15 и 1 сообщение из битов 1, 0, 1 даёт сумму 11.

**Лёгкий ранец** задаёт последовательность, в которой каждый элемент больше суммы предшествующих. Это свойство называют супервозрастанием. Когда известна сумма выбранных весов такого ранца, можно определить биты, рассматривая веса от большего к меньшему. Вариант «на степенях» строит последовательность из степеней одного основания. Вариант «на супервозрастающей последовательности» требует самого свойства без привязки к степеням.

**Тяжёлый ранец** получают из лёгкого. Каждый вес умножают на одно и то же число и берут остаток от деления на модуль. Модуль больше суммы весов лёгкого ранца. Множитель и модуль взаимно просты, то есть их единственный общий положительный делитель равен единице. Поэтому у множителя есть обратный по этому модулю — число, произведение которого на множитель при делении на модуль даёт остаток один. При расшифровании обратный множитель позволяет перейти от шифртекста к сумме весов лёгкого ранца. Открытой частью ключа для шифрования служит тяжёлый ранец. Лёгкий ранец и параметры преобразования образуют закрытые данные для расшифрования. В учебном условии часть величин специально раскрывают студенту.

Далее описаны программные обязанности по [системным требованиям к ранцевым задачам](../04_Системные_требования/Ранцевые_задачи.md). **Предметный обработчик** — модуль, который выдаёт условие определённого типа и проверяет ответ по данным именно этой задачи. **Решатель** строит полное эталонное решение для самоподготовки.

| Логическая часть | Ответственность |
|---|---|
| Участие в сессиях | По имени, под которым ранцевый модуль зарегистрирован в программе, направить ему запрос на выдачу или проверку задачи |
| Генерация условия | Построить условие выбранного варианта с частично скрытыми данными и сохранить его в составе сессии |
| Проверка решения | Проверить ответ по величинам криптосистемы и вернуть вердикт с диагностикой |
| Редакционные решатели | Построить эталонную задачу по варианту или с параметрами пользователя |
| Диспетчеризация | Выбрать решатель по варианту редакционного запроса |
| Хранение | Сохранять условия сгенерированных задач между запусками |

В [контракте сессий](Контракты_сессий.md) заданы поля, типы и коды ошибок, в [разделе DOC-08](../09_Архитектура_и_API/DOC-08_API_сессий.md) описаны действия клиента. Для задач в сессии внешний тип — `BACKPACK`. Поле `type` внутри решения указывает математический вариант выданного ранцевого задания.

### Условие и его состав

Условие ранцевой задачи хранится вместе с конкретной задачей сессии как объект JSON — текстовое представление именованных полей со значениями. Оно содержит вариант, выданные фрагменты лёгкого ранца, тяжёлый ранец и данные, достаточные для восстановления остальных величин. После выдачи условие не формируется заново по шаблону: проверка использует его сохранённую копию, что соответствует [составу созданной сессии](DOC-06_Программные_требования.md#swr-sys-003-состав-созданной-сессии).

Приоритет всех программных требований документа — обязательный. Источники SR указывают на определения в DOC-05; сценарии приведены в [таблице проверок](#7-трассировка-и-описательные-проверки).

## 2. Участие в сессиях

<a id="swr-knap-001"></a>

### SWR-KNAP-001. Регистрация предметного обработчика

Управление сессиями получает задачи, заданные шаблоном, через предметных обработчиков. Квалификатор «Backpack» — имя, под которым ранцевый модуль зарегистрирован для вызова из подсистемы сессий. По этому имени управление сессиями передаёт модулю формирование задания и проверку решения. Так состав набора задаётся без знания внутренних алгоритмов домена. Это применение [общего контракта предметного обработчика](DOC-06_Программные_требования.md#swr-sys-004-контракт-предметного-обработчика) для ранцевого типа.

**Требование.** Обработчик ранцевых задач должен быть доступен управлению сессиями под квалификатором «Backpack» и вызываться для задач, тип которых задан этим квалификатором в шаблоне.

Вызов генерации происходит при создании набора, вызов проверки — после допуска ответа. Обработчик не получает и не изменяет правила срока, попытки и принадлежности: они остаются у управления сессиями. Порядок вызова определён в [формировании задач](DOC-06.2_Сессии_задач_и_планировщик.md#swr-ses-004-формирование-задач) и [передаче профильной проверке](DOC-06.2_Сессии_задач_и_планировщик.md#swr-ses-010-передача-профильной-проверке).

Источники: [SR-KNAP-001]; [SWR-SYS-004].

<a id="swr-knap-002"></a>

### SWR-KNAP-002. Случайный выбор варианта

Ранцевая часть шаблона не различает учебные варианты: оба вида заданий обслуживаются одним квалификатором. Конкретный вариант каждого задания выбирается при генерации так, чтобы состав набора не предопределял тип всех ранцевых задач. Выбор не управляется параметрами пользователя и не зависит от предыдущих задач сессии.

**Требование.** При генерации задачи для сессии ПО должно выбирать вариант случайно из двух поддерживаемых.

Выбранный вариант фиксируется в сохранённом условии и далее используется проверкой без повторного выбора. Системное основание — [выбор варианта ранцевой задачи](../04_Системные_требования/Ранцевые_задачи.md#sr-knap-001-выбор-варианта-ранцевой-задачи).

Источник: [SR-KNAP-001].

## 3. Генерация условия

Студент получает условие с частью [величин ранцевого шифра](#как-устроена-ранцевая-задача). Для последующей проверки у платформы остаются данные того же варианта. Правила ниже определяют размер сообщения, форму весов и состав выдачи. Размерность — число весов в каждом ранце, равное числу битов сообщения.

<a id="swr-knap-003"></a>

### SWR-KNAP-003. Генерация сообщения

Сообщение определяет, какие элементы тяжёлого ранца суммируются при шифровании, и входит как в условие, так и в проверяемый ответ. Учебное сообщение должно быть коротким для ручного решения и содержать достаточно нулей, чтобы расшифровка жадным алгоритмом была наглядной.

**Требование.** Сгенерированное сообщение должно быть случайной последовательностью логических значений длиной от 3 до 5 с долей ложных значений не менее трети.

Сгенерированное сообщение сохраняется в условии и сравнивается с переданным в ответе. Параметры длины относятся к задачам в сессиях; редакционные генерации принимают сообщение пользователя по [SWR-KNAP-013].

Источники: [SR-KNAP-001], [SR-KNAP-002].

<a id="swr-knap-004"></a>

### SWR-KNAP-004. Сокрытие параметров условия

Выдача полного набора данных превратила бы задание в чтение ответа. Поэтому условие скрывает большую часть лёгкого ранца, оставляя открытыми отдельные элементы, и может не содержать множитель. Степень сокрытия ограничена требованием восстанавливаемости: по условию должны однозначно достраиваться все величины криптосистемы.

**Требование.** В условии открытыми должны оставаться не более двух элементов лёгкого ранца; множитель преобразования может не включаться в условие.

Сокрытие выполняется при генерации и сохраняется вместе с условием: повторное чтение сессии выдаёт те же данные. Восстановление скрытого опирается на математические свойства последовательности варианта; полная проверка достроенных величин выполняется по [SWR-KNAP-009]. Системное основание — [частично скрытое условие](../04_Системные_требования/Ранцевые_задачи.md#sr-knap-002-частично-скрытое-условие).

Источник: [SR-KNAP-002].

<a id="swr-knap-005"></a>

### SWR-KNAP-005. Супервозрастающий лёгкий ранец

Для супервозрастающего варианта лёгкий ранец обязан строго возрастать: каждый элемент больше суммы всех предыдущих. Это свойство используется и жадной расшифровкой, и проверкой ответа. Последовательность, переданная или построенная с нарушением свойства, не образует допустимую криптосистему данного варианта.

**Требование.** Для супервозрастающего варианта лёгкий ранец должен быть приведён к строго супервозрастающей последовательности заданной размерности.

Приведение выполняется при генерации; размерность соответствует параметрам задачи. Проверка ответа повторно устанавливает свойство для переданного ранца — см. [SWR-KNAP-009].

Источники: [SR-KNAP-001], [SR-KNAP-004].

<a id="swr-knap-006"></a>

### SWR-KNAP-006. Лёгкий ранец на степенях

Вариант на степенях строит лёгкий ранец из последовательных степеней выбранного основания. Такая последовательность автоматически сверхвозрастает, что сохраняет применимость общей схемы проверки. Основание выбирается из фиксированного набора простых чисел.

**Требование.** Для варианта на степенях элементы лёгкого ранца должны строиться как степени выбранного основания.

Выбранное основание сохраняется в данных генерации. После разбора корректных десятичных строк проверяющий сопоставляет целые значения элементов со степенями этого основания. Системное основание — [вариант на степенях](../04_Системные_требования/Ранцевые_задачи.md#sr-knap-006-вариант-на-степенях).

Источники: [SR-KNAP-001], [SR-KNAP-006].

<a id="swr-knap-007"></a>

### SWR-KNAP-007. Сохранение сгенерированной задачи

Построенное условие должно стать данными создаваемой сессии, а не промежуточным значением в памяти генератора. Вместе с условием сохраняются вариант и принадлежность задачи. Отказ генерации или сохранения обрабатывается общим правилом полного набора: частичная сессия не остаётся активной.

**Требование.** Построенная задача должна сохраняться вместе с вариантом и принадлежностью, а её условие — передаваться в состав создаваемой сессии до подтверждения операции создания.

Сохранённое условие затем используется при проверке без повторной генерации. Транзакционные границы операции создания определены [правилом сохранения набора](DOC-06.2_Сессии_задач_и_планировщик.md#swr-ses-005-сохранение-созданного-набора) домена сессий; ранцевой обработчик участвует в ней как источник условия.

Источники: [SR-KNAP-001], [SR-KNAP-002]; [SWR-SYS-003], [SWR-SES-004].

## 4. Проверка решения

Решение передаётся в полях, перечисленных в [контракте ранцевой задачи](Контракты_сессий.md#ранцевая-задача). Сначала компонент проверяет форму, например что список весов передан массивом десятичных строк. Затем он проверяет значения по [выданному условию](#условие-и-его-состав). Вердикт означает результат математической проверки. Ошибка формы оставляет предметную попытку доступной до общего срока.

<a id="swr-knap-008"></a>

### SWR-KNAP-008. Предварительная сверка ответа

Для обоих вариантов используется одна [схема решения](Контракты_сессий.md#ранцевая-задача). Она задаёт десять обязательных полей. Размерность передаётся положительным целым JSON-числом, вариант — строкой из выданного условия, исходное и расшифрованное сообщения — массивами логических значений. Для элементов ранцев и остальных целых величин установлена запись десятичными строками. Ни одно обязательное поле не принимает `null`.

**Требование.** Перед математической проверкой ПО должно сверить состав и типы полей со схемой решения и сравнить строку варианта с вариантом сохранённого условия. При несовпадении варианта или нарушении схемы клиент получает `400 INVALID_REQUEST` без предметного вердикта.

Переданный вариант сравнивается с вариантом сохранённого условия: совпадение обязательно, подмена не допускается. Ошибка формы сохраняет попытку; далее допустимый ответ передаётся математической проверке. Разделение стадий следует [правилу проверки формата](DOC-06.2_Сессии_задач_и_планировщик.md#swr-ses-009-проверка-формата) домена сессий.

Источники: [SR-KNAP-003]; [SR-SES-009], [SWR-SES-009], [SWR-SES-022].

<a id="swr-knap-009"></a>

### SWR-KNAP-009. Пошаговая проверка величин

Предметная проверка перебирает величины криптосистемы по установленному порядку: длину и элементы сообщений и ранцев, сверхвозрастаемость, соотношение модуля с суммой лёгкого ранца, взаимную простоту множителя, тяжёлый ранец, обратный множитель, шифртекст и расшифрованное сообщение. Расшифровка выполняется жадным алгоритмом по супервозрастающей последовательности; дополнительно устанавливается положительность элементов ранцев.

**Требование.** ПО должно проверять величины, перечисленные в [SR-KNAP-004], поэтапно, включая расшифровку жадным алгоритмом по супервозрастающей последовательности и положительность элементов ранцев.

Для обоих вариантов проверка охватывает расшифрованное сообщение. Если остальные величины верны, но расшифрованное сообщение отличается от ожидаемого, результат проверки отрицательный. Вычисление не запускает собственных фоновых процессов. Его длительность входит в [предел обработки](DOC-06.2_Сессии_задач_и_планировщик.md#swr-ses-020-предел-обработки) принятого ответа. При истечении предела операция завершается техническим отказом без предметного вердикта.

Источник: [SR-KNAP-004]; [SR-SES-012].

<a id="swr-knap-010"></a>

### SWR-KNAP-010. Диагностика неверной величины

Первая несовпавшая величина определяет текст диагностики. Пояснение относится к завершённой неверной попытке и позволяет студенту найти ошибку в собственной цепочке вычислений. Дальнейшие величины после первого несовпадения не сравниваются: вердикт уже определён.

**Требование.** При первом несовпадении ПО должно возвращать вердикт «неверно» с указанием величины, не прошедшей проверку.

После фиксации вердикта интерфейс возвращает `200 OK`. Верный ответ даёт `isOk = true` и `errorMessage = null`. При неверном ответе `isOk = false`, а строка `errorMessage` указывает первую величину, для которой обнаружена ошибка. Оба вердикта завершают попытку. Категории отказов определены в [контракте ошибок](Контракты_сессий.md#коды-и-представление-ошибок).

Источник: [SR-KNAP-005].

<a id="swr-knap-011"></a>

### SWR-KNAP-011. Защита итогового состояния

Повторное обращение к завершённой задаче не должно запускать математическую проверку. Решение принимается по сохранённым данным задачи, поэтому состояние клиента и повторные соединения не влияют на запрет второй попытки. Восстановление отображения выполняется чтением сессии. Если повторное прохождение контрольной разрешено, оно создаёт отдельную сессию с новыми задачами. Запрет второй попытки на прежней задаче продолжает действовать.

**Требование.** Если задача уже завершена, управление сессиями должно отклонить новый ответ до вызова ранцевого проверяющего. Сохранённый результат остаётся доступным для чтения.

Для владельца итоговой задачи код отказа зависит от времени получения полного запроса. До общего срока сессии действует `409 TASK_FINALIZED`, начиная с общего срока — `410 SESSION_EXPIRED`. Запрос к чужой либо отсутствующей задаче получает `404 TASK_NOT_FOUND`. Порядок установлен [правилами допуска](DOC-06.2_Сессии_задач_и_планировщик.md#swr-ses-008-проверка-допуска) и [сохранения итогового состояния](DOC-06.2_Сессии_задач_и_планировщик.md#swr-ses-013-сохранение-итогового-состояния).

Источники: [SR-KNAP-007]; [SR-SES-008], [SWR-SES-013].

## 5. Редакционные генерации

Редакционный пример — отдельное учебное задание с полным эталонным решением для самоподготовки. Можно запросить пример по названию варианта или задать часть математических параметров. Выбор программы, решающей задачу указанного варианта, ниже назван диспетчеризацией.

<a id="swr-knap-012"></a>

### SWR-KNAP-012. Генерация по варианту

Редакционный запрос без дополнительных параметров выдаёт эталон выбранного варианта. Недостающие данные выбираются системой: основание — из фиксированного набора простых чисел, остальные параметры — по правилам варианта. Результат содержит полный набор величин и служит материалом для разбора решения.

**Требование.** Запрос выбранного варианта без дополнительных параметров должен строить эталон с полным решением; параметры, не указанные в запросе, выбираются ПО, в том числе основание — из фиксированного набора простых чисел.

Редакционная генерация не связана с сессиями: она не проверяет допуски и не расходует попытки. Состав выдачи соответствует [эталонной задаче](../04_Системные_требования/Ранцевые_задачи.md#sr-knap-008-редакционная-задача-по-варианту).

Источник: [SR-KNAP-008].

<a id="swr-knap-013"></a>

### SWR-KNAP-013. Генерация с параметрами

Параметры преподавателя делают эталон воспроизводимым в методических целях: размерность, вариант, сообщение, лёгкий ранец и множитель задаются запросом. Система проверяет математическую допустимость до построения; нарушение взаимной простоты множителя с модулем делает обратное преобразование невозможным и отклоняется.

**Требование.** Запрос с параметрами должен использовать переданные размерность, вариант, сообщение, лёгкий ранец и множитель; взаимная простота множителя с модулем должна проверяться до построения эталона.

Отклонение сопровождается диагностикой причины; частично построенный эталон не выдаётся. Отказ редакционной генерации не влияет на сессии и попытки.

Источник: [SR-KNAP-009].

<a id="swr-knap-014"></a>

### SWR-KNAP-014. Диспетчеризация по варианту

В редакционной генерации вариант указывает преподаватель. Один и тот же выбор действует при запросе эталона без параметров и при задании собственных параметров. Для запроса на степенях лёгкий ранец должен состоять из степеней выбранного основания. Одной сверхвозрастаемости элементов недостаточно, чтобы признать такой эталон верным.

**Требование.** Редакционный запрос должен направляться решателю соответствующего варианта.

Выбор выполняется по варианту запроса; результат диспетчеризации — эталон, соответствующий указанному варианту по составу величин.

Источники: [SR-KNAP-008], [SR-KNAP-009].

<a id="swr-knap-015"></a>

### SWR-KNAP-015. Генерация без сохранения

Редакционные примеры не являются попытками и не должны попадать в хранилище сессий. Результат строится на лету и возвращается напрямую; повторный запрос выполняет генерацию заново.

**Требование.** Результаты редакционных генераций не должны записываться в хранилище.

Правило не затрагивает сохранение задач, создаваемых в сессиях по [SWR-KNAP-007].

Источник: [SR-KNAP-010].

## 6. Хранение

<a id="swr-knap-016"></a>

### SWR-KNAP-016. Сохранность условий

Условия сгенерированных ранцевых задач должны переживать перезапуск приложения: вместе с вариантом и принадлежностью они образуют данные, по которым выполняется проверка и чтение результата. Списковые величины хранятся в текстовом представлении колонок и восстанавливаются без изменения значений.

**Требование.** Условия сгенерированных ранцевых задач должны сохраняться между запусками приложения вместе с вариантом и принадлежностью; списковые величины — в текстовом представлении; сохранённые условия доступны для просмотра истории.

Сохранённые условия читаются историей задач без повторной генерации. Общие границы сохранения и восстановления определены [правилом сохранности](DOC-06_Программные_требования.md#swr-sys-008-сохранность-завершённых-данных) DOC-06.

Источники: [SR-SYS-007]; [SWR-SYS-008].

## 8. Разбор граничных случаев

Следующие случаи используют один исходный набор с каждой задачей в состоянии `NEW` (решение ещё не зафиксировано). Результаты `SOLVED` и `FAILED` и их влияние на набор определены в [таблице состояний сессии](DOC-06.2_Сессии_задач_и_планировщик.md#swr-ses-018-общая-функция-итога-сессии). Отправки в таблице рассматриваются независимо. Кроме случая с истечением срока, запрос владельца принят своевременно и обработка успевает закончиться в пределах 60 секунд от получения запроса.

| Входные данные | Ожидаемый результат |
|---|---|
| Клиент прислал полное решение, но указал в `type` другой вариант ранца | `400 INVALID_REQUEST`. Обработчик не подставляет другой вариант, предметный результат отсутствует, попытка сохраняется |
| Обязательное поле `module` передано JSON-числом | `400 INVALID_REQUEST`. Клиент может исправить тип и отправить новое решение до общего срока сессии |
| Вариант совпал, поля имеют заданные типы, но значение модуля математически неверно | При фиксации — `200 OK` с `isOk = false`; задача получает `FAILED`, а пояснение называет первую неверную величину |
| У задачи на степенях все величины верны, кроме одного бита расшифрованного сообщения | Отрицательный предметный результат указывает на расшифрованное сообщение. При чтении возвращается тот же вердикт |
| Каждая переданная величина верна | После фиксации — `200 OK`, задача в состоянии `SOLVED`, поле `errorMessage` присутствует со значением `null` |
| Проверяющий получил верный ответ, но вердикт не зафиксирован к моменту «получение полного запроса + 60 секунд» | `503 CHECK_TIMEOUT`, предметный результат отсутствует. Повтор возможен только до общего срока открытой задачи |
| Владелец направил решение контрольной ранцевой задачи ровно в момент закрытия мероприятия, хотя с создания сессии ещё не прошло 20 минут | Подсистема сессий возвращает `410 SESSION_EXPIRED` до вызова ранцевого обработчика. Своевременно полученный ответ может завершиться после закрытия в пределах исходных 60 секунд. |
