# DOC-13.1. Протокол формальной инспекции технического задания

**Справка для чтения архивной формы.** Техническое задание (ТЗ) определяет назначение системы и требования к ней. Формальная инспекция ТЗ (ФИ-ТЗ) — совместная проверка предъявленной версии этого документа. Автор отвечает на вопросы по тексту, рецензент проверяет порученную ему область, ведущий организует обсуждение, а секретарь записывает фактические замечания и решение заседания.

Перечень контрольных вопросов (чек-лист) помогает выявить ошибки, пропуски и неверные связи с другими требованиями. Эти три стороны проверки в форме названы корректностью, полнотой и трассируемостью. ID — постоянное обозначение документа или замечания. Префикс DEF указывает на зарегистрированное замечание. Степень Major означает существенную ошибку, Minor — локальный недочёт без изменения смысла. Типы CONTENT, STD, TRACE и COMPLETE обозначают соответственно содержание, оформление или правила комплекта, связь требований и полноту. В конце формы D — число замечаний на страницу, S — число страниц за час, E — доля принятых замечаний, найденных до совещания. Спринт — плановый период работы команды. Этот абзац поясняет обозначения первоначальной формы.

Заготовка протокола по [форме DOC-04](../../06_Процедура_формальной_инспекции/Процедура_формальной_инспекции.tex). Заполняется секретарём по ходу совещания; поля с подчёркиваниями заполняются по факту проведения инспекции. Настоящая заготовка не подтверждает факт проведения совещания и не содержит решений.

## Решение инспекции

Отметить одно:

- ( ) **ПРИНЯТО** — документ принимается без изменений; все замечания закрыты и подтверждены на момент решения.
- ( ) **ПРИНЯТО С ЗАМЕЧАНИЯМИ** — открыты только Minor; срок закрытия — до конца следующего спринта; контроль закрытия — ведущий.
- ( ) **НА ДОРАБОТКУ** — имеются незакрытые Major либо существенная переработка; назначается повторная формальная инспекция.
