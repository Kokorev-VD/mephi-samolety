Материалы второго и третьего спринтов; актуализация части Самбьюи от 25.11.2026. Комплект включает техническое задание, ПУКПО, системные и программные требования, архитектуру, полный справочник API и план верификации. Редактор сводных требований — Анохин Г.А. Владельцы документов и статус редакций указаны в исходниках. Подготовка и печатная сборка сами по себе не подтверждают принятие или проведение формальной инспекции.

## Контрольное мероприятие

Контрольное мероприятие — работа по курсу для одной учебной группы. Администратор назначает преподавателю группы, которыми тот может управлять. Студент регистрируется с учётной записью личного кабинета МИФИ или привязывает её к уже существующему профилю платформы. Система получает номер группы из подтверждённых сведений МИФИ. В расписании студента появляются опубликованные работы для его группы. [Принадлежность к группе](02_Техническое_задание/DOC-02_Техническое_задание.md#ts-req-func-group-join), [права преподавателя и администратора](02_Техническое_задание/DOC-02_Техническое_задание.md#ts-req-sec-roles).

Преподаватель выбирает задания и их порядок. Для своего текстового задания он записывает варианты, у каждого есть условие и эталонный ответ. Черновик можно сохранить пустым. Для публикации нужна хотя бы одна позиция. Преподаватель выбирает, разрешено ли повторное прохождение, а при публикации указывает свою группу и два момента — начало и конец работы. Карточка сразу видна группе. Время начала открывает доступ автоматически, в момент окончания сервер прекращает принимать новые ответы. [Состав и публикация](02_Техническое_задание/DOC-02_Техническое_задание.md#ts-req-func-event-publish).

При старте создаётся личная сессия — запись одного прохождения. На работу даётся до 20 минут. Если контрольная закрывается в 10:30, студент, начавший в 10:25, может сдавать ответы лишь до 10:30. При разрешённом повторе студент после завершения своей сессии может начать новую, пока работа открыта. Для каждого текстового задания в сессии закрепляется случайный вариант. При сравнении с эталоном система удаляет крайние пробелы в обоих ответах и сохраняет регистр и внутренние пробелы. [Срок и попытка](02_Техническое_задание/DOC-02_Техническое_задание.md#ts-req-func-session-time), [проверка текстового ответа](02_Техническое_задание/DOC-02_Техническое_задание.md#ts-req-func-task-assign).

## Сборка

Markdown служит редактируемым источником. Генератор [build_pdf.py](build_pdf.py) объединяет связанные разделы, преобразует ссылки и создаёт самостоятельные `.tex` и `.pdf`. Общее оформление задано в [шаблоне](latex/document.tex): A4, шрифт 12 pt, полуторный интервал, поля 25/15/20/20 мм, титульный лист, журнал изменений и оглавление.

Для сборки нужны Python 3, Pandoc и Tectonic. Если программы доступны в PATH:

```sh
python3 docs/build_pdf.py
```

Пути к исполняемым файлам можно передать параметрами `--pandoc` и `--tectonic`. В среде с MiKTeX вместо Tectonic можно использовать `--pdflatex pdflatex`; выполняются повторные проходы до стабилизации оглавления и ссылок. Режим `--tex-only` создаёт LaTeX без компиляции PDF. Журналы сборки и вспомогательные файлы сохраняются в `docs/.build/`, готовые результаты — рядом с основными Markdown-исходниками. Все текстовые исходники и результаты генерации используют UTF-8.

Сгенерированные `.tex` также допускают прямую сборку `pdflatex` в два прохода при наличии пакетов исходного оформления репозитория. Изменения содержания вносятся в Markdown с повторной сборкой, чтобы три представления одного документа оставались одинаковыми.

Для одновременного обновления печатных копий в корневых папках используйте `python3 docs/build_pdf.py --root-copies`. Копируются только `.tex` и `.pdf`; ссылки в них рассчитываются для соответствующего расположения.

Например, для обновления только технического задания и связанных с ним сводных документов выполните команду:

```sh
python3 docs/build_pdf.py --root-copies --only DOC-02 DOC-05 DOC-06 DOC-08 DOC-10
```

Для актуализированной части Самбьюи в среде с Pandoc и MiKTeX:

```sh
python docs/build_pdf.py --pdflatex pdflatex --root-copies --only DOC-03 DOC-05 DOC-06 DOC-06.6
```

Основной файл системных требований в корне — `04_Системные_требования/Системные_требования.pdf`; он обновляется вместе с одноимённым `.tex` и копией с префиксом `DOC-05`. Все эти файлы содержат одну текущую редакцию.
